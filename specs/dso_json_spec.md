# `dso.json` Spec — Deep-Sky Object Catalog Feed

## Purpose

`dso.json` is AstroPlanner's primary catalog of deep-sky objects (galaxies,
nebulae, clusters, double stars). It is generated by `dso_catalog.ipynb` in
`AstroPlannerData` from OpenNGC + a SIMBAD fallback + manual last-resort
data, and published via GitHub Pages at:

```
https://jeffrwatts.github.io/AstroPlannerData/mobile/dso.json
```

Downloaded on-device via `Config.DSO_URL`. `dso_catalog.ipynb` produces
**only** this JSON file — it does no image handling. Object thumbnail/gallery
images and their catalog (`images.json`) are a separate pipeline
(`image_processing_web.ipynb`, uploading to Cloudinary); see
`images_json_spec.md`.

## Format

A JSON array of objects, one per deep-sky object.

```json
[
  {
    "displayName": "Double Cluster (NGC 869 & 884)",
    "objectId": "ngc869",
    "ra": 2.3162667,
    "dec": 57.11725,
    "type": "cluster",
    "subType": "Open Cluster",
    "constellation": "Perseus",
    "recommended": true,
    "angularSizeMajor": 14.4,
    "angularSizeMinor": null,
    "magnitude": 3.7
  }
]
```

## Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `displayName` | string | yes | Human-readable name shown in the UI (e.g. `"Leo Triplet"`, `"Double Cluster (NGC 869 & 884)"`). |
| `objectId` | string | yes | Stable lowercase identifier, no spaces/punctuation (e.g. `"ngc869"`, `"leotriplet"`). Natural key — also used to join against `images.json` and to name the object's `.webp` thumbnail. |
| `ra` | number | yes | Right ascension in **decimal hours**, range `[0, 24)`. The app multiplies by 15 to store degrees internally. **Not** decimal degrees. |
| `dec` | number | yes | Declination in **decimal degrees**, signed, range `[-90, 90]`. |
| `type` | string | yes | Coarse object category, must match AstroPlanner's `ObjectType` enum: `"galaxy"`, `"nebula"`, `"cluster"`, or `"star"`. Always derived from `subType` (see below) — never set independently. |
| `subType` | string | yes | Finer classification, free text from a fixed vocabulary the notebook maintains (e.g. `"Spiral Galaxy"`, `"Emission Nebula"`, `"Open Cluster"`, `"Double Star"`). `type` is a many-to-one mapping of this field. |
| `constellation` | string | no | IAU constellation full name (e.g. `"Perseus"`, `"Boötes"`). Falls back to an RA/Dec → IAU-boundary lookup (`astropy.coordinates.get_constellation`) when the data source doesn't supply one. Omit or `null` if unresolvable. |
| `recommended` | boolean | yes | Whether this object should surface in AstroPlanner's "recommended" curated list. Set per-object in the notebook's input list (Cell 1), not derived from any external data. |
| `angularSizeMajor` | number \| null | no | Apparent angular size (major axis) in **arcminutes**. `null` if unknown. |
| `angularSizeMinor` | number \| null | no | Apparent angular size (minor axis) in **arcminutes**. `null` if unknown or the object has no meaningfully distinct minor axis (e.g. round/ambiguous objects). |
| `magnitude` | number \| null | no | A single representative magnitude. `null` if unknown — several manually-curated multi-object groupings (e.g. `"leotriplet"`, `"markarian"`) have no single well-defined magnitude and are always `null` here. |

## Lookup order and precedence (context, not part of the wire format)

For each `objectId` in the notebook's input list, data is resolved in this
order — **first match wins**:

1. **OpenNGC** (`mattiaverga/OpenNGC` CSV) — matched by translating the
   `objectId` to an OpenNGC `NGCxxxx`/`ICxxxx` name (with a small
   alias table for Messier numbers OpenNGC doesn't carry directly, e.g.
   `m102` → `NGC5866`).
2. **`MANUAL_DATA`** (hardcoded in the notebook) — last-resort fixed
   RA/Dec/subType/magnitude/size for objects that can't be resolved
   programmatically (non-standard multi-object groupings like
   `"leotriplet"`, `"whalehockey"`, `"m81m82"`, `"markarian"`,
   `"m106ngc4217"`, `"rhoophiuchi"`).
3. **SIMBAD** — queried for anything OpenNGC can't resolve (Sharpless,
   Barnard, LDN catalog entries, etc.).

`MANUAL_DATA` is checked before SIMBAD specifically so a partial/wrong
SIMBAD result can never silently override an intentional manual entry.

`subType` can additionally be force-corrected per-`objectId` via a
`SUBTYPE_OVERRIDES` table in the notebook, for cases where the resolved
source classification is wrong or not the desired astrophotography framing
(e.g. OpenNGC classifies M42's embedded cluster, but the notebook overrides
it to `"Emission Nebula"` since that's the astrophotography subject).
`type` is always re-derived from the (possibly overridden) `subType`.

## What the app does with it (for context, not to implement in the notebook)

- Fetches the URL with a cache-busting query param, same pattern as
  `vs.json`/`images.json`.
- Full-replace sync on import (catalog rows are re-derived from this feed
  each time, not diffed/merged).
- `objectId` is the join key used to attach a thumbnail image from
  `images.json`, when one exists for that object.
