# `images.json` Spec — Object Thumbnail Image Feed

## Purpose

`images.json` is AstroPlanner's catalog of astrophotography thumbnail
images — one entry per DSO/planet/moon/sun that Jeff has an exported final
image for. It is generated by `image_processing.ipynb` in
`AstroPlannerData`, which also produces the `.webp` image files it
references. Both are published via GitHub Pages:

```
https://jeffrwatts.github.io/AstroPlannerData/mobile/images.json
https://jeffrwatts.github.io/AstroPlannerData/mobile/<objectId>.webp
```

Downloaded on-device via `Config.IMAGES_URL`.

Unlike `dso.json`/`vs.json`, this feed is **not limited to `dso.json`
objects** — it also covers `objectId`s that have no deep-sky catalog entry
at all (planets: `"venus"`, `"mars"`, `"jupiter"`, `"saturn"`; and
`"moon"`, `"sun"`). For those, `displayName`/`ra`/`dec`/`constellation`
have no source data and are handled specially (see field reference).

## Format

A JSON array of objects, one per image.

```json
[
  {
    "objectId": "barnard72",
    "displayName": "Snake Nebula",
    "ra": 17.3941667,
    "dec": -23.695,
    "constellation": "Ophiucus",
    "thumbX": null,
    "thumbY": null,
    "thumbDim": null,
    "url": "https://jeffrwatts.github.io/AstroPlannerData/mobile/barnard72.webp"
  }
]
```

## Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `objectId` | string | yes | Stable lowercase identifier. For DSOs, matches the corresponding `dso.json` `objectId` — this is the join key. For planets/moon/sun, is the lowercase body name (`"moon"`, `"sun"`, `"venus"`, `"mars"`, `"jupiter"`, `"saturn"`) with no `dso.json` counterpart. |
| `displayName` | string | yes | Human-readable name. Sourced from the matching `dso.json` entry when one exists; otherwise falls back to the capitalized `objectId` (e.g. `"moon"` → `"Moon"`) since planets/moon/sun aren't in `dso.json`. |
| `ra` | number \| null | no | Right ascension in **decimal hours**, sourced from the matching `dso.json` entry. `null`/absent for `objectId`s with no `dso.json` match (planets, moon, sun). |
| `dec` | number \| null | no | Declination in **decimal degrees**, sourced from the matching `dso.json` entry. `null`/absent for `objectId`s with no `dso.json` match. |
| `constellation` | string \| null | no | Sourced from the matching `dso.json` entry. `null`/absent for `objectId`s with no `dso.json` match. |
| `thumbX` | number \| null | no | Pixel X coordinate for a pinned thumbnail crop region, intended to let a specific object of interest within a wide-field image be pinned as the thumbnail focus. **Currently always `null`** — the notebook adds the column but has no override mechanism wired up yet to populate it per-object. Treat as reserved/future, not a load-bearing field today. |
| `thumbY` | number \| null | no | Pixel Y coordinate, paired with `thumbX`. Same current-always-`null` caveat. |
| `thumbDim` | number \| null | no | Crop region size (square side length in pixels), paired with `thumbX`/`thumbY`. Same current-always-`null` caveat. |
| `url` | string | yes | Full GitHub Pages URL to the `.webp` image, e.g. `"https://jeffrwatts.github.io/AstroPlannerData/mobile/barnard72.webp"`. Always `{GITHUB_PAGES_BASE}/{objectId}.webp`. |

## Image file details (context, not part of the JSON wire format)

- Source images live outside this repo, under
  `/Users/jwatts/Documents/astrophotography/Exports/`, and are **not**
  committed — only the resized `.webp` output lands in `mobile/`.
- Folder → `objectId` discovery:
  - `Exports/DSO/<FolderName>/` → `objectId` = folder name lowercased; picks
    the most-recently-modified `.jpg`/`.jpeg` in that folder.
  - `Exports/Planet/<Planet>/<session>/` → `objectId` = planet folder name
    lowercased; picks the most-recently-modified session subfolder, then
    the most-recently-modified image within it.
  - `moon` and `sun` have **no** auto-discovery folder convention and must
    always be set explicitly via `image_overrides` (Cell 1) — the notebook
    raises an error if `"moon"` is missing from the resulting image map.
  - Any `objectId` (DSO or planet) can optionally be pinned to a specific
    file via `image_overrides`, overriding auto-discovery.
- Processing: EXIF orientation is applied, image is downscaled (Lanczos)
  to a max height of 1080px if taller (width scaled proportionally, aspect
  preserved), then saved as WEBP at quality 88 to `mobile/<objectId>.webp`.
- Re-running the notebook fully regenerates every `.webp` and the entire
  `images.json` — this is a full-replace pipeline, not incremental.

## What the app does with it (for context, not to implement in the notebook)

- Fetches the URL with a cache-busting query param, same pattern as
  `dso.json`/`vs.json`.
- `objectId` is the join key back to `dso.json` (when present) to show a
  thumbnail alongside a DSO's other catalog data.
- `thumbX`/`thumbY`/`thumbDim` are reserved for a future "pin the thumbnail
  crop" feature — since they're always `null` today, the app should treat
  a missing/null value as "use a sensible default crop/fit", not as an
  error condition.
