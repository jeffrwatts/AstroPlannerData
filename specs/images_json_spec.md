# `images.json` Spec — Image Gallery/Thumbnail Feed

## Purpose

`images.json` is the catalog of astrophotography images used by both
IslandSkiesWeb (gallery) and AstroPlanner (thumbnails). It is generated by
`image_processing_web.ipynb` in `AstroPlannerData`, which also produces the
JPEG image files it references, and uploads both the images and the
manifest itself to Cloudinary:

```
https://res.cloudinary.com/jeffrwatts/raw/upload/island-skies-astro/images.json
https://res.cloudinary.com/jeffrwatts/image/upload/island-skies-astro/<category>/<imageId>
```

AstroPlanner fetches `images.json` from Cloudinary and builds full image
URLs from each entry's `cloudinaryId`. There is no longer a GitHub
Pages-hosted `mobile/images.json` or `mobile/*.webp` — `image_processing.ipynb`
(the old mobile-only pipeline that produced those) has been retired.

Covers both DSO images (joined against `dso.json` for metadata) and
solar-system images (planets, moon, sun, comets) which have no `dso.json`
counterpart.

## Format

A JSON array of objects, one per image.

```json
[
  {
    "id": "ic1318",
    "title": "Sadr Region / Crescent area (IC 1318)",
    "category": "dso",
    "objectId": "ic1318",
    "region": null,
    "cloudinaryId": "island-skies-astro/dso/ic1318",
    "altText": "IC 1318 - Sadr Region / Crescent area (IC 1318)",
    "objectName": "Sadr Region / Crescent area (IC 1318)",
    "catalogId": "IC 1318",
    "ra": 20.3704694,
    "dec": 40.2566944,
    "constellation": "Cygnus",
    "objectType": "nebula",
    "objectSubType": "Emission Nebula",
    "filename": "ic1318.jpg",
    "width": 6173,
    "height": 4145,
    "sortOrder": 12,
    "contextChart": "island-skies-astro/charts/ic1318-context"
  }
]
```

## Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | yes | Stable image identifier (`imageId`). Usually matches `objectId`, but an object can have multiple images distinguished by a suffix (e.g. `"m42-2"`, or a `<objectId>-<region>` form for DSO region crops). |
| `title` | string | yes | Display title — the object's `displayName`, optionally suffixed with a human-readable region name for region crops (e.g. `"M16 - Pillars Of Creation"`). |
| `category` | string | yes | `"dso"` or `"solar-system"`. Determines the Cloudinary folder and which metadata fields are populated. |
| `objectId` | string | yes | Stable lowercase identifier. For DSOs, matches `dso.json`'s `objectId` — the join key. For solar-system images, the lowercase body name (`"moon"`, `"venus"`, etc.) with no `dso.json` counterpart. |
| `region` | string \| null | no | Set only for DSO images that are a named crop/region of a larger object (e.g. `"pillarsOfCreation"`); `null` otherwise. |
| `cloudinaryId` | string | yes | Full Cloudinary public ID for the image, `island-skies-astro/<dso\|solarsystem>/<id>`. Combine with the Cloudinary cloud name (`jeffrwatts`) and desired transformation to build a delivery URL. |
| `altText` | string | yes | Accessibility alt text. For DSO images, `"<catalogId> - <title>"` (or just `<catalogId>` if title matches); for solar-system, just `title`. |
| `objectName` | string | yes | Same as `title` — the object's display name, duplicated under this key for consumers that expect an `objectName` field. |
| `catalogId` | string \| null | no | Formatted catalog designation (e.g. `"IC 1318"`) for DSO images; `null` for solar-system. |
| `ra` | number \| null | no | Right ascension in **decimal hours**, sourced from `dso.json`. `null` for solar-system images. |
| `dec` | number \| null | no | Declination in **decimal degrees**, sourced from `dso.json`. `null` for solar-system images. |
| `constellation` | string \| null | no | Sourced from `dso.json`. `null` for solar-system images. |
| `objectType` | string \| null | no | Sourced from `dso.json`'s `type` (`"galaxy"`, `"nebula"`, `"cluster"`, `"star"`). `null` for solar-system images. |
| `objectSubType` | string \| null | no | Sourced from `dso.json`'s `subType`. `null` for solar-system images. |
| `filename` | string | yes | Local output filename, `<id>.jpg`. Not needed to build a Cloudinary URL (use `cloudinaryId` instead) — informational. |
| `width` | number | yes | Image width in pixels, as processed (post EXIF-transpose, pre any Cloudinary transformation). |
| `height` | number | yes | Image height in pixels, as processed. |
| `sortOrder` | number \| null | no | Manual gallery pin order (ascending; lower sorts first). `null` for images with no pinned position — those should sort after all pinned images, by whatever secondary order the consumer chooses. |
| `contextChart` | string \| null | no | Cloudinary public ID of a dark-themed constellation finder chart for this object (`island-skies-astro/charts/<objectId>-context`), only ever set for `category = "dso"` entries where a chart was generated. `null` otherwise. |

Some images are entirely excluded from the manifest (an `EXCLUDE` set in the
notebook, e.g. duplicate/inferior takes of the same object) — their absence
is intentional, not a data gap.

## Image file details (context, not part of the JSON wire format)

- Source images live outside this repo, under
  `/Users/jwatts/Documents/astrophotography/Exports/`, and are **not**
  committed.
- Folder → `objectId`/`category` discovery covers `Exports/DSO/`,
  `Exports/Planet/`, `Exports/Comet/`, `Exports/Lunar/`, `Exports/Solar/`
  (the last three map to `category = "solar-system"`).
- DSO images are re-compressed as JPEG (quality 95, stepping down to a
  minimum of 80 if needed to stay under Cloudinary's 10 MB free-tier
  limit); solar-system images are copied through unchanged (already small).
- Both the images and `images.json` are uploaded to Cloudinary
  (`cloudinary.uploader.upload`, `overwrite=True, invalidate=True`).
  Uploads are content-hashed (`web/upload_hashes.json`) so unchanged files
  are skipped on re-run.
- Constellation context charts (dark-themed finder charts, one per DSO
  object) are generated and uploaded separately, then patched into the
  manifest as `contextChart`. See `context_charts_feature` notes for detail
  on chart generation.
- Re-running the notebook fully regenerates `images.json` and re-uploads
  any changed images/charts — this is a full-replace manifest, incremental
  asset upload.

## What consumers do with it (context only — not dictated)

- IslandSkiesWeb: gallery UI, filtered/sorted by `category` and
  `sortOrder`, using `cloudinaryId` to build responsive image URLs via
  Cloudinary transformations.
- AstroPlanner: fetches this feed for object thumbnails, using `cloudinaryId`
  to build the image URL and `objectId` to join back to `dso.json` for the
  rest of an object's catalog data.
