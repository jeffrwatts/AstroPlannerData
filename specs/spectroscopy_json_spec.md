# `spectroscopy.json` Spec: Spectroscopy Star Feed

## Purpose

`spectroscopy.json` lists **stars** worth collecting low-resolution spectra of
with a slitless grating (Star Analyser SA-100). It is generated by
`spectroscopy_catalog.ipynb` in `AstroPlannerData` and published via GitHub
Pages alongside `dso.json`/`vs.json`:

```
https://jeffrwatts.github.io/AstroPlannerData/mobile/spectroscopy.json
```

It is a curated, hand-picked list, not a catalog dump: a few easy, bright
examples of each Morgan-Keenan (MK) spectral class (O, B, A, F, G, K, M) plus
spectrally distinctive groups (carbon stars, Be stars, Wolf-Rayet stars),
spread across the year.

**Spectroscopy DSOs are not in this feed.** A DSO that is a spectroscopy
target (e.g. M57, a compact planetary nebula) lives in `dso.json` with
`"spectroscopy"` in its `lists` field; see `dso_json_spec.md`. This feed only
holds objects that exist in no other feed.

## Format

A JSON array of objects, one per star. The app should deserialize with
`ignoreUnknownKeys = true`.

```json
[
  {
    "objectId": "vega",
    "type": "star",
    "displayName": "Vega",
    "ra": 18.615649,
    "dec": 38.7836889,
    "subType": "A",
    "spectralType": "A0V",
    "constellation": "Lyra",
    "magnitude": 0.03,
    "colorIndexBV": 0.0,
    "calibrationStar": true,
    "spectralFeatures": "Strong hydrogen Balmer absorption series (Hα, Hβ, Hγ, Hδ...)"
  },
  {
    "objectId": "ycvn",
    "type": "star",
    "displayName": "La Superba (Y CVn)",
    "ra": 12.7548,
    "dec": 45.4402,
    "subType": "Carbon",
    "spectralType": "C-N5",
    "constellation": "Canes Venatici",
    "magnitude": 4.87,
    "colorIndexBV": 2.54,
    "calibrationStar": false,
    "spectralFeatures": "C2 Swan bands and CN absorption; almost no blue light"
  }
]
```

## Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `objectId` | string | yes | Stable lowercase identifier, no spaces/punctuation, derived from `displayName`: the parenthetical designation if there is one, Greek letters spelled out SIMBAD-style (`"Vega"` → `"vega"`, `"La Superba (Y CVn)"` → `"ycvn"`, `"ζ Oph"` → `"zetoph"`, `"γ² Vel"` → `"gam2vel"`, `"WR 136"` → `"wr136"`). Must not collide with any `objectId` in `dso.json` or `vs.json`; the notebook validates this. |
| `type` | string | yes | Always `"star"` today. Kept as a discriminator (same pattern as `vs.json`) so other kinds of spectroscopy-only rows can be added later. Any other value should be treated as unrecognized/skip. The app maps `"star"` to its internal `SPECTROSCOPY_STAR` type (distinct from `STAR`, which `dso.json` uses for double stars). |
| `displayName` | string | yes | Proper name where one is in common use (`"Vega"`, `"Betelgeuse"`); nickname plus designation where the nickname alone is ambiguous (`"La Superba (Y CVn)"`); otherwise the designation (`"10 Lac"`, `"TX Psc"`, `"WR 136"`). |
| `ra` | number | yes | Right ascension in **decimal hours**, `[0, 24)`. Same convention as `dso.json`/`vs.json`. |
| `dec` | number | yes | Declination in **decimal degrees**, `[-90, 90]`. |
| `subType` | string | yes | Spectroscopy grouping from a fixed vocabulary: `"O"`, `"B"`, `"A"`, `"F"`, `"G"`, `"K"`, `"M"`, `"Carbon"`, `"Be"`, `"Wolf-Rayet"`. Set explicitly per star in the notebook's Cell 1. It is a curation choice, not parsed from `spectralType` (e.g. δ Sco is grouped as `"Be"` although SIMBAD's type string `B0.3IV` has no `e`). |
| `spectralType` | string \| null | no | Full MK classification as published by SIMBAD (e.g. `"B8Ia"`, `"K1.5IIIFe-0.5"`, `"C-N5"`, `"WC8+O7.5III-V"`). Display as-is; group by `subType`, don't parse this. |
| `constellation` | string \| null | no | IAU full name, from RA/Dec via `astropy.coordinates.get_constellation`. |
| `magnitude` | number \| null | no | V magnitude from SIMBAD. Several targets are variable (carbon stars, Betelgeuse, γ Cas), so treat this as typical, not current. |
| `colorIndexBV` | number \| null | no | B−V color index from SIMBAD. A rough indicator of the spectrum's slope: negative for hot blue O/B stars, +2 to +4 for carbon stars. |
| `calibrationStar` | boolean | yes | `true` for bright, unreddened, non-peculiar A0 to A1 dwarfs (or late-B dwarfs) suitable as an instrument response reference (see below). |
| `spectralFeatures` | string \| null | no | Short plain-text note on what to look for. The notebook supplies a default per `subType`, overridable per star in Cell 1. |

### What `calibrationStar` means

A raw SA-100 spectrum is the star's true spectrum multiplied by the
instrument response (camera sensitivity × grating efficiency × atmospheric
transmission at that altitude). To remove it, you image a reference star
whose true spectrum is well known, divide its observed spectrum by a library
spectrum of the same type, and use the result as a correction curve for the
target. A0V stars are the standard choice: smooth continuum, few lines other
than hydrogen, and good library spectra (Pickles, MILES). The reference works
best close to the target in altitude on the same night, so the list has at
least one per season.

These stars are also the easiest **wavelength** calibration source: the
Balmer lines are deep, widely spaced, and at known wavelengths.

`calibrationStar` is not a separate list. A calibration star is an ordinary
`"A"` (or `"B"`) target; the flag lets the app answer "which response
reference is near my target tonight?"

## Data sources (notebook context, not wire format)

- One SIMBAD query per star (identifier given in Cell 1) for RA/Dec,
  `sp_type`, V, B.
- A `MANUAL_DATA` table covers SIMBAD gaps (e.g. a missing V magnitude). It
  is checked before SIMBAD values are accepted, same precedence rule as
  `dso_catalog.ipynb`.
- The notebook checks each star's SIMBAD `sp_type` against its Cell 1
  `subType` (first letter `O`–`M`, `C` for carbon, `W` for Wolf-Rayet) and
  prints a warning, not an error, on mismatch. Be stars are exempt.
- `objectId` collisions with the local `mobile/dso.json` and `mobile/vs.json`
  are a hard error.

## Selection guidance

- **Brightness:** an SA-100 spreads a star's light into a line, so V ≲ 5 is
  easy, V 5–8 needs longer exposures, fainter is a stretch.
- **Year-round coverage:** each `subType` should ideally have a target in each
  season, and at least one `calibrationStar` per season. The app derives
  visibility from RA/Dec; this feed doesn't store seasons.
- **Observer latitude:** about +20° (Hawaii), so targets down to about −45°
  declination (e.g. γ² Vel) are usable.

## What the app does with it (context, not dictated)

- Fetch with a cache-busting query param, same as the other feeds.
- Imported as part of the single catalog refresh described in
  `dso_json_spec.md`: all `userAdded = 0` rows are deleted and the DSO,
  variable star and spectroscopy feeds re-inserted together, with RA
  hours × 15 → degrees. User-added rows are untouched.
- Needs new nullable columns on `celestialObject`: `spectralType`,
  `colorIndexBV`, `calibrationStar`, `spectralFeatures`.
- The **Spectroscopy** filter button shows `SPECTROSCOPY_STAR` rows plus
  `dso.json` rows whose `lists` contains `"spectroscopy"`.
